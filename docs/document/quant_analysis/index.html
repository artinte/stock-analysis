1. 什么是量化分析？

量化分析（Quantitative Analysis）是使用数学、统计学、计算机程序和数据， 将投资研究过程转化为可以计算、验证和重复执行的分析方法。

传统投资研究可能会这样进行：

“我感觉这只股票趋势不错，估值也不高，可能值得买入。”

量化研究则会进一步追问：

  • “趋势不错”具体如何定义？
  • “估值不高”使用什么指标衡量？
  • 这个条件在过去十年是否有效？
  • 如果同时有 3000 只股票满足条件，应该买哪些？
  • 每只股票买多少？
  • 交易成本和滑点是多少？
  • 最大回撤是多少？
  • 换一个市场环境，策略是否仍然有效？

量化的价值就在于： 将模糊的投资想法转化为明确的规则，再使用历史数据检验这些规则。

量化不等于高频交易

量化是一个很大的领域，并不只指高频交易。

类型 典型特点 常见研究内容
量化选股 根据因子筛选股票 价值、成长、质量、动量
趋势策略 根据价格趋势交易 均线、突破、动量
均值回归 研究价格偏离与回归 价差、布林带、统计偏离
统计套利 研究相关资产之间的统计关系 配对交易、协整
组合优化 在风险约束下配置资产 权重、波动率、相关性
高频 / 算法交易 高频率、低延迟执行 订单簿、微观结构、执行算法

对个人投资者和股票研究平台而言， 最适合的起点通常是： 日线数据 + 因子研究 + 量化选股 + 组合回测。

2. 量化系统到底解决什么问题？

一个量化系统的目标，不是单纯生成一个“买入”或“卖出”字符串， 而是把整个研究和交易流程标准化。

2.1 从人工判断到可执行规则

例如，一个模糊的投资想法是：

“选择趋势向上、估值合理、盈利质量较好的股票。”

量化系统需要把它拆解为：

  1. 趋势向上：收盘价高于 MA60，且 MA60 向上。
  2. 估值合理：PE TTM 处于指定范围内。
  3. 盈利质量较好：ROE、现金流或利润增长满足条件。
  4. 股票池：只研究指定市场和可交易股票。
  5. 调仓频率：每周或每月执行一次。
  6. 仓位规则：最多持有 N 只股票，单只股票不超过组合的一定比例。

2.2 量化系统的基本闭环

研究假设 例如：低估值、强趋势、盈利改善可能与未来收益有关。
↓
数据 获取历史行情、财务、估值、行业和交易状态数据。
↓
因子 将原始数据转换成可比较的数值特征。
↓
策略 根据因子或价格规则生成选股、买入、卖出和持仓信号。
↓
回测 在历史时间轴上模拟资金、持仓、订单、成交和收益。
↓
评估 分析收益、回撤、波动率、换手率、稳定性和风险。
↓
模拟盘 / 实盘 使用实时数据和真实交易规则检验策略的可执行性。

3. 量化系统的完整架构

如果要搭建一个长期维护的量化平台， 最重要的不是先写策略，而是先设计模块边界。

一个较完整的量化系统，可以分为以下几个层次。

层级 主要职责 输出
数据接入层 从行情、财务、新闻、交易接口获取数据 原始数据
数据标准化层 清洗、去重、复权、统一字段和时间 标准化数据集
数据存储层 保存历史数据、版本、更新时间和元数据 可复用数据
因子层 计算技术、基本面、估值和风险因子 因子矩阵
策略层 将因子转换成选股和交易规则 信号、目标持仓
组合层 决定仓位、权重、资金和风险约束 目标组合
回测层 模拟订单、成交、资金、持仓和成本 回测结果
执行层 将目标订单发送到券商或交易接口 订单、成交记录
监控层 监控数据、策略、订单、风险和系统异常 日志、告警、报告

3.1 研究系统与交易系统的区别

量化平台通常包含两个相互关联但职责不同的系统。

研究系统 Research

用于探索想法、计算因子、分析数据、回测策略和生成研究报告。

特点：灵活、可实验、允许频繁修改。

交易系统 Trading

用于读取实时数据、生成交易指令、检查风险、发送订单和记录成交。

特点：稳定、可控、可追踪，不能因为研究代码修改而影响正在运行的交易逻辑。

一个常见的工程原则是：

研究代码可以快速迭代，交易代码必须谨慎变更。

4. 第一步：明确研究目标

在写任何代码之前，首先要明确你究竟想研究什么。 不同目标需要完全不同的数据、策略和回测方式。

4.1 先确定市场

  • A 股
  • 港股
  • 美股
  • ETF
  • 期货
  • 加密资产

不同市场的交易制度不同，例如交易时间、涨跌停、T+1、 做空机制、最小交易单位和手续费结构。 这些都会影响策略能否真实执行。

4.2 再确定投资周期

周期 典型策略 主要要求
日内 日内动量、突破、做市 高频数据、执行质量、低延迟
日线 趋势、动量、量化选股 稳定的日线和财务数据
周线 中期趋势、行业轮动 中长期数据和换手控制
月度 多因子、价值、质量、资产配置 财务数据、组合优化、长期回测

4.3 写下研究假设

一个好的量化研究应该从假设开始，而不是从“哪个指标最赚钱”开始。

例如：

研究假设：
过去一段时间表现较强的股票，
在控制行业、规模和交易成本后，
未来一段时间是否仍然具有相对收益？

这个假设可以对应“动量因子”研究。

再例如：

研究假设：
估值较低、盈利质量较高的股票，
是否具有更好的长期风险收益特征？

这就对应价值与质量因子研究。

5. 第二步：搭建行情与基础数据层

数据是量化系统的地基。 如果数据存在错误，后面再复杂的因子和模型也没有意义。

5.1 量化系统需要哪些数据？

数据类型 典型字段 用途
日线行情 open、high、low、close、volume、amount K 线、技术指标、回测
分钟行情 时间、价格、成交量、成交额 日内策略、执行研究
股票基本信息 symbol、name、exchange、listing_date 股票池、上市时间、市场分类
财务报表 revenue、net_profit、assets、cash_flow 基本面因子、质量因子
估值数据 PE、PB、PS、market_cap 价值因子、估值分析
公司行为 分红、送股、拆股、配股 复权、收益计算
交易状态 停牌、涨跌停、ST、上市状态 可交易性判断
行业与指数 industry、index_membership、index_price 行业中性、基准比较

5.2 原始数据与计算数据必须分开

这是量化系统中非常重要的设计原则。

例如，原始行情数据应该保存： 

symbol
trade_date
open
high
low
close
volume
amount

而 MA20、RSI、MACD、动量等属于计算结果， 不应该和原始行情混在一起当作同一种数据。

原因包括：

  • 不同策略可能使用不同参数。
  • 指标可以重新计算。
  • 原始数据修正后，需要重新生成计算结果。
  • 便于排查数据错误和复现研究结果。
  • 避免某个策略修改了数据后影响其他策略。

5.3 数据接口应该统一

你的 STOCK LAB 已经在做 Gateway / DataManager 这一类数据抽象， 这个方向非常适合继续扩展到量化系统。

策略不应该关心底层数据究竟来自哪个供应商。 

strategy
    ↓
DataManager
    ↓
StockDataGateway
    ↓
Yinhe / AkShare / TDX / Tencent

例如，策略只需要请求： 

history = data.get_daily_bars(
    symbol="600519.SH",
    start_date="2020-01-01",
    end_date="2025-12-31",
)

而不应该在策略内部直接调用某个供应商的专有 API。

工程建议： 数据源负责“获取数据”， 数据标准化负责“统一数据”， 因子负责“计算特征”， 策略负责“研究逻辑”。 不要让一个策略文件同时负责这四件事。

6. 第三步：数据清洗、标准化与存储

获取数据只是开始。 量化研究真正困难的部分之一，是确保数据在时间上、字段上和统计意义上可靠。

6.1 数据清洗

常见清洗工作包括：

  • 统一股票代码格式。
  • 统一日期格式和时区。
  • 处理重复记录。
  • 处理缺失值。
  • 检查价格和成交量的异常值。
  • 检查停牌、退市和上市日期。
  • 检查财务数据的报告期和公告日期。
  • 处理分红、送股、拆股等公司行为。

6.2 复权是什么？

股票发生分红、送股或拆股后， 历史价格可能出现不连续变化。

例如股票发生拆股时， 价格可能按照比例调整， 但投资者实际持有的经济价值并不一定发生同等幅度的损失。

为了研究连续收益，常见数据处理方式包括：

  • 前复权
  • 后复权
  • 不复权

不同用途应该选择合适的数据口径。

数据口径 常见用途 注意事项
不复权 研究实际交易价格、盘口和部分执行场景 公司行为可能导致价格不连续
前复权 技术分析、连续价格走势研究 历史价格会随后续公司行为调整
后复权 某些长期收益展示和价格序列研究 价格尺度与实际历史交易价格不同

6.3 财务数据更需要“时间意识”

行情数据通常按交易日组织， 但财务数据还涉及报告期、公告日和数据可用日。

例如：

2024 年年度报告对应的财务数据，
不一定在 2024-12-31 当天已经可以被市场知道。

如果回测在 2024-12-31 就使用了后来才公布的年度财务数据， 就会产生未来信息泄漏。

因此基本面量化必须尽可能区分：

  • 报告期：财务数据描述的是哪个期间。
  • 公告日：公司何时发布报告。
  • 可用日：策略在什么时间点真正可以使用这条数据。

7. 第四步：什么是因子？

因子（Factor）是量化研究中用于描述资产某种特征的变量。

简单来说，因子就是： 把原始数据转换成可以用于比较、排序或建模的数值。

7.1 从原始数据到因子

例如，原始数据中有： 

symbol       close       revenue       net_profit
600519.SH    1500.00     150000000000  80000000000
000858.SZ    120.00      80000000000   30000000000

可以计算出： 

PE = market_cap / net_profit

ROE = net_profit / average_equity

Momentum20 = close / close.shift(20) - 1

Volatility20 = daily_return.rolling(20).std()

这些计算结果就是可以用于量化研究的因子或特征。

7.2 常见因子分类

因子类型 代表因子 研究逻辑
价值 Value PE、PB、PS、股息率 研究估值水平与未来收益的关系
动量 Momentum 过去收益率、价格突破 研究价格趋势延续
质量 Quality ROE、ROA、利润率、现金流 研究企业盈利质量和经营稳定性
成长 Growth 营收增长、利润增长、现金流增长 研究企业未来经营扩张能力
波动率 Volatility 收益率标准差、ATR 研究价格风险和波动特征
流动性 Liquidity 成交额、换手率、买卖价差 研究交易容量和执行难度
规模 Size 总市值、流通市值 研究规模与收益、风险的关系
技术 Technical MA、RSI、MACD、布林带 研究价格、趋势和动能特征

7.3 因子不是策略

这是初学者非常容易混淆的地方。

因子

描述某种特征，例如“过去 20 日收益率”。

它本身只是一个变量，不一定直接决定买卖。

策略

使用一个或多个因子，制定选股、排序、仓位和交易规则。

例如：每月买入动量排名前 20% 的股票，并进行行业约束。

可以理解为：

因子 = 特征
策略 = 使用特征做决策的规则

8. 第五步：如何计算技术因子？

技术因子通常从价格和成交量出发， 是最适合入门量化研究的一类因子。

8.1 收益率因子

最基本的收益率是：

Return(t) = Close(t) / Close(t-1) - 1

N 日动量可以写为：

Momentum(N) = Close(t) / Close(t-N) - 1

例如 Momentum20 表示过去 20 个交易日的价格变化。

8.2 均线因子

可以将均线直接转换为因子：

MA20 = Close.rolling(20).mean()

MA60 = Close.rolling(60).mean()

MA_Ratio = Close / MA60 - 1

MA_Ratio 表示当前价格相对于 MA60 的偏离程度。

也可以构造趋势状态： 

trend_up = (
    (close > ma20)
    &
    (ma20 > ma60)
)

8.3 波动率因子

常见做法是计算历史收益率的滚动标准差。

Volatility20 = Std(Return(t-19), ..., Return(t))

波动率越高，代表近期价格变化越剧烈。 但高波动并不必然意味着高收益或低收益， 它更多描述的是风险和价格行为特征。

8.4 成交量因子

例如成交量相对于过去平均成交量的变化：

Volume_Ratio20 = Volume / Volume.rolling(20).mean()

这个因子可以用于研究：

  • 放量突破
  • 缩量回调
  • 成交活跃度
  • 流动性变化

8.5 Python 示例：计算技术因子

下面是一个简单的 Pandas 因子计算示例。 假设数据已经按照交易日期升序排列。 

from __future__ import annotations

import pandas as pd


def calculate_technical_factors(
    df: pd.DataFrame,
) -> pd.DataFrame:

    result = df.copy()

    close = result["close"]
    volume = result["volume"]

    result["return_1d"] = close.pct_change()

    result["momentum_20"] = (
        close / close.shift(20) - 1
    )

    result["momentum_60"] = (
        close / close.shift(60) - 1
    )

    result["ma_20"] = (
        close.rolling(20).mean()
    )

    result["ma_60"] = (
        close.rolling(60).mean()
    )

    result["price_to_ma60"] = (
        close / result["ma_60"] - 1
    )

    result["volatility_20"] = (
        result["return_1d"]
        .rolling(20)
        .std()
    )

    result["volume_ratio_20"] = (
        volume
        / volume.rolling(20).mean()
    )

    result["trend_up"] = (
        (close > result["ma_20"])
        & (result["ma_20"] > result["ma_60"])
    )

    return result

注意： 这段代码只是因子计算，不是完整交易策略。 它没有处理复权口径、停牌、交易成本、股票池、信号时间和订单执行。 真正回测前，还需要进一步处理这些问题。

9. 第六步：如何计算基本面因子？

基本面因子主要来自财务报表、估值数据和公司经营信息。

9.1 价值因子

常见价值因子包括：

因子 常见公式 解释
PE 市值 ÷ 净利润 价格相对于盈利的水平
PB 市值 ÷ 净资产 价格相对于账面价值的水平
PS 市值 ÷ 营业收入 价格相对于收入的水平
Dividend Yield 每股股息 ÷ 股价 股息相对于价格的水平

这些指标不能简单地直接横向比较所有行业。 例如银行、软件、周期、消费和制造业的资产结构、 盈利模式和估值区间可能差异很大。

9.2 质量因子

质量因子试图衡量企业盈利能力、经营效率和财务稳健程度。

  • ROE：净资产收益率
  • ROA：总资产收益率
  • 毛利率
  • 净利率
  • 经营现金流质量
  • 资产负债率
  • 利润与现金流匹配程度

9.3 成长因子

成长因子通常研究企业经营指标在一段时间内的变化。

Revenue_Growth = Revenue(t) / Revenue(t-1) - 1

Profit_Growth = NetProfit(t) / NetProfit(t-1) - 1

需要注意： 单纯的高增长不一定意味着高质量。 如果增长来自高杠杆、一次性收益或低基数， 其可持续性可能较弱。

9.4 财务因子必须使用可用数据

这是基本面量化和普通财务分析之间非常重要的区别。

普通财务分析可能会直接使用“最新修订后的财务数据”。 但历史回测必须模拟当时市场能够看到的信息。

研究某个历史交易日时，只能使用当时已经公开且可获得的数据。

10. 第七步：因子检验与有效性分析

计算出一个因子，并不代表它有效。 因子研究的核心是判断： 这个特征是否与未来收益存在稳定、可重复、具有经济意义的关系？

10.1 因子研究的基本流程

01
计算因子

对每个股票、每个交易日计算因子值。

02
定义未来收益

例如未来 5 日、20 日或 60 日收益。

03
横截面排序

在同一个交易日，将股票按照因子值排序。

04
分组回测

将股票分成多个组，观察不同组的未来收益。

05
检查稳定性

检查不同年份、行业、市场环境和样本外时期的表现。

10.2 什么是分组回测？

假设某一天有 1000 只股票， 根据动量因子从低到高排序， 分成 5 组：

组别 因子水平 研究意义
Q1 因子最低的 20% 低因子组
Q2 20% - 40% 较低因子组
Q3 40% - 60% 中间组
Q4 60% - 80% 较高因子组
Q5 因子最高的 20% 高因子组

然后比较每组未来收益。

如果 Q5 长期明显优于 Q1， 说明这个因子可能具有一定的排序能力。

但还需要进一步检查：

  • 是否只是某一个年份贡献了全部收益？
  • 是否被某一个行业主导？
  • 是否存在极端值影响？
  • 是否忽略了交易成本？
  • 是否存在未来数据泄漏？
  • 是否在样本外仍然有效？

10.3 IC：因子与未来收益的相关性

IC（Information Coefficient）常用于衡量因子值与未来收益之间的横截面相关性。

IC(t) = Corr(Factor(t), FutureReturn(t))

在实际因子研究中， 常见的是使用 Spearman Rank Correlation， 因为它关注排序关系，而不是严格的线性关系。

因子研究不应该只看 IC 的均值， 还应该关注：

  • IC 均值
  • IC 标准差
  • ICIR
  • IC 正值比例
  • IC 随时间的稳定性
ICIR = Mean(IC) / Std(IC)

ICIR 可以帮助研究者了解因子信号相对于自身波动的稳定程度， 但它不是收益保证，也不能脱离样本和统计显著性单独判断。

10.4 因子中性化

一个因子看起来有效， 可能只是因为它与规模、行业或其他已知特征相关。

例如，一个“低 PE”策略可能大量买入银行股。 最终收益到底来自低估值，还是来自银行行业特征？

为了回答这个问题，可以进行：

  • 行业中性化
  • 市值中性化
  • Beta 中性化
  • 风格因子中性化

中性化不是所有策略都必须做， 但它是理解因子真实来源的重要研究工具。

11. 第八步：从因子到选股策略

因子研究的下一步，是将因子转换为实际的选股规则。

11.1 最简单的单因子选股

例如，使用过去 60 日收益率作为动量因子：

每月调仓：
1. 计算所有股票的 Momentum60
2. 按 Momentum60 从高到低排序
3. 选择排名前 50 的股票
4. 等权持有

这已经是一个完整的量化策略雏形。

11.2 多因子选股

多因子策略会将多个因子组合起来。

例如：

综合评分 =
0.4 × 动量评分
+ 0.3 × 质量评分
+ 0.2 × 价值评分
+ 0.1 × 低波动评分

这里的权重只是示例， 不代表真实有效的最优配置。

实际研究中，权重可以通过：

  • 等权
  • 研究者设定
  • 历史统计
  • 回归模型
  • 优化算法
  • 机器学习模型

但越复杂的权重优化，越容易产生过拟合， 因此复杂度必须与样本量和研究目标匹配。

11.3 因子标准化

不同因子的量纲可能不同。 例如 PE 是倍数，动量是百分比，ROE 也是百分比。 如果直接相加，可能导致某些因子主导结果。

常见处理方式包括：

  • 排名标准化
  • Z-Score 标准化
  • 分位数转换
  • 去极值
Z-Score = (Factor - Mean) ÷ StandardDeviation

但标准化参数也必须使用当时可用的数据计算， 不能用全样本未来数据计算历史时点的均值和标准差。

12. 第九步：策略信号如何生成？

策略层的任务是将研究逻辑转换为明确的信号。 一个好的策略定义必须能够回答“何时、买什么、买多少、何时卖”。

12.1 策略的四个核心部分

部分 需要回答的问题
股票池 哪些股票允许进入研究和交易？
入场规则 什么条件下建立仓位？
出场规则 什么条件下减仓或卖出？
仓位规则 每只股票买多少，组合持有多少？

12.2 示例：均线趋势策略

假设我们设计一个非常简单的日线策略：

当 MA20 高于 MA60，且收盘价高于 MA20 时， 认为趋势偏强； 当 MA20 低于 MA60 时，退出仓位。 

entry = (
    (close > ma20)
    &
    (ma20 > ma60)
)

exit = (
    ma20 < ma60
)

这个规则看起来简单， 但真正回测时还必须明确：

  • 信号是在收盘时生成，还是盘中生成？
  • 是当天收盘成交，还是下一个交易日开盘成交？
  • 如果当天涨停，是否能够买入？
  • 如果当天停牌，是否能够卖出？
  • 如果已经持仓，是否每天重复下单？
  • 交易手续费如何计算？

这些细节决定了回测结果是否可信。

12.3 信号与订单不是一回事

这是搭建量化系统时必须明确的概念。

Signal：信号

策略认为应该做什么。

例如：目标持仓为 10%。

Order：订单

系统实际准备发送给交易接口的指令。

例如：以某种价格买入 1000 股。

Fill：成交

交易所或券商实际返回的成交结果。

例如：成交 600 股，成交均价为某个价格。

实盘中，信号不一定会立即变成成交。 订单可能被拒绝、部分成交、撤单或延迟成交。

13. 第十步：如何搭建回测系统？

回测（Backtesting）是将策略规则应用到历史数据， 模拟过去如果按照这套规则交易，可能产生什么结果。

回测的本质不是“证明策略赚钱”， 而是检查策略在历史样本中的行为和风险特征。

13.1 回测系统需要模拟什么？

模块 模拟内容
时间引擎 按交易日或交易事件推进
数据引擎 在每个时点提供当时可用的数据
策略引擎 计算因子、生成信号
组合引擎 计算目标权重、资金和仓位
订单引擎 模拟下单、成交、撤单和部分成交
费用模型 模拟佣金、印花税、过户费、滑点等
账户引擎 更新现金、持仓、市值和净值
分析引擎 计算收益、回撤、风险和交易统计

13.2 回测的基本时间循环

一个最基本的事件驱动回测逻辑可以理解为：

读取当前交易日 t 获取当前时点允许使用的数据。
↓
更新指标和因子 只能使用 t 时点之前已经可用的信息。
↓
策略生成目标持仓 例如目标持仓从 0% 变为 10%。
↓
订单撮合与成本计算 根据成交规则、价格、滑点和手续费模拟成交。
↓
更新账户 更新现金、持仓、净值和交易记录。
↓
进入下一个交易日 重复执行整个流程。

13.3 向量化回测与事件驱动回测

Python 量化系统中常见两种回测方式。

向量化回测 Vectorized Backtest

使用 Pandas / NumPy 一次性计算大量时间序列， 然后根据信号计算收益。

优点：开发快、适合研究、适合大量参数实验。

缺点：复杂成交逻辑、部分成交、资金约束和多资产事件处理较难表达。

事件驱动回测 Event-driven Backtest

按时间顺序逐步处理数据事件、信号事件、订单事件和成交事件。

优点：更接近真实交易系统，适合复杂组合和实盘扩展。

缺点：开发成本更高，调试和性能优化更复杂。

对你的项目，我建议：

早期研究使用向量化回测快速验证想法， 当策略和交易模型逐渐稳定后，再建设事件驱动回测核心。

13.4 一个教学版向量化回测示例

下面示例展示一个非常简化的均线策略回测。 它用于理解基本思想，不代表完整的生产级回测引擎。 

from __future__ import annotations

import pandas as pd


def backtest_ma_strategy(
    df: pd.DataFrame,
    initial_capital: float = 100_000.0,
) -> pd.DataFrame:

    data = df.copy()
    data = data.sort_index()

    data["ma20"] = (
        data["close"].rolling(20).mean()
    )

    data["ma60"] = (
        data["close"].rolling(60).mean()
    )

    data["signal"] = (
        (
            (data["close"] > data["ma20"])
            &
            (data["ma20"] > data["ma60"])
        )
        .astype(int)
    )

    # 使用下一交易日的信号，
    # 避免直接使用当前收盘价产生不现实的成交。
    data["position"] = (
        data["signal"].shift(1).fillna(0)
    )

    data["return"] = (
        data["close"].pct_change().fillna(0)
    )

    data["strategy_return"] = (
        data["position"] * data["return"]
    )

    data["equity"] = (
        initial_capital
        * (1 + data["strategy_return"]).cumprod()
    )

    return data

这段代码表达了一个核心思想：

当前持仓收益 = 当前资产收益 × 上一个时点确定的持仓

但它仍然非常简化，实际使用时还需要加入：

  • 交易成本
  • 滑点
  • 停牌与涨跌停
  • 资金约束
  • 真实成交价格
  • 仓位变化与换手率
  • 多股票组合

14. 第十一步：回测中的收益与风险指标

判断策略不能只看“赚了多少钱”。 一个年化收益很高但最大回撤极大的策略， 可能并不适合实际投资。

14.1 累计收益率

CumulativeReturn = FinalEquity / InitialEquity - 1

它描述从开始到结束的总收益。

14.2 年化收益率 CAGR

CAGR = (FinalEquity / InitialEquity) ^ (1 / Years) - 1

年化收益率用于将不同时间长度的策略进行一定程度的比较。

14.3 最大回撤 Maximum Drawdown

最大回撤表示净值从历史高点到之后低点的最大跌幅。

Drawdown(t) = Equity(t) / RunningMax(Equity) - 1

最大回撤是投资者实际体验风险的重要指标。

14.4 夏普比率 Sharpe Ratio

夏普比率用于衡量单位风险下的超额收益。

Sharpe Ratio = (Annualized Return - RiskFreeRate) ÷ Annualized Volatility

实际计算时需要明确收益频率、无风险利率和年化方式。 不同实现方式可能导致数值差异。

14.5 其他重要指标

指标 关注什么
Calmar Ratio 年化收益与最大回撤的关系
Sortino Ratio 重点关注下行波动的风险调整收益
Volatility 收益波动程度
Win Rate 盈利交易占比
Profit Factor 总盈利与总亏损绝对值之比
Turnover 组合换手程度
Exposure 资金处于市场风险中的比例
Benchmark 与沪深 300、中证 500或其他基准比较

不要只看收益曲线。 一条平滑的回测曲线可能来自未来函数、幸存者偏差、 过低的成本假设、过度优化或不现实的成交模型。

15. 第十二步：组合构建与仓位管理

选出股票只是量化系统的一半。 真正决定组合风险的，还有买多少、持有多少以及如何控制集中度。

15.1 等权组合

假设选出 20 只股票，等权配置：

每只股票权重 = 1 / 20 = 5%

等权组合简单、透明、容易实现， 是量化选股的常见起点。

15.2 市值加权

按股票市值决定权重。 这是很多市场指数常见的构建方式。

优点是交易相对自然， 缺点是可能对大市值股票产生较高集中度。

15.3 因子加权

可以根据综合评分或风险调整后的评分配置权重。

但需要警惕： 如果权重过度集中在少数股票， 组合可能失去分散化效果。

15.4 常见风险约束

  • 单只股票最大权重。
  • 单个行业最大权重。
  • 单个市场或资产类别最大权重。
  • 最低流动性要求。
  • 最大组合波动率。
  • 最大杠杆比例。
  • 最大换手率。
  • 组合与基准的偏离限制。

15.5 风险管理不是策略失败后的补救

风险管理应该在策略设计阶段就存在， 而不是等到回撤发生后才考虑。

策略负责产生预期收益来源， 组合负责决定风险暴露， 风控负责限制不可接受的损失。

16. 第十三步：交易成本与滑点

很多看起来优秀的回测策略， 在加入交易成本后可能明显变差。

16.1 交易成本包括什么？

  • 佣金
  • 印花税
  • 过户费
  • 买卖价差
  • 滑点
  • 市场冲击成本
  • 融资融券或借券成本（适用时）

16.2 什么是滑点？

滑点是预期成交价格与实际成交价格之间的差异。

例如：

预期买入价格：10.00 元
实际成交价格：10.03 元
滑点：0.03 元

对高换手策略而言， 即使单次滑点很小，长期累计影响也可能很大。

16.3 换手率为什么重要？

假设两个策略年化毛收益相同：

  • 策略 A：每月调仓一次，换手较低。
  • 策略 B：每天频繁交易，换手很高。

策略 B 可能因为成本更高， 最终净收益反而更低。

因此回测报告应该同时展示：

  • 毛收益
  • 净收益
  • 交易成本
  • 换手率
  • 成交金额

17. 第十四步：避免未来函数与回测偏差

回测中最危险的问题之一，是使用了当时不可能知道的信息。 这类问题会让策略看起来远比现实优秀。

17.1 什么是未来函数？

未来函数（Look-ahead Bias）是指： 在历史某个时点做决策时，使用了该时点之后才会出现的数据。

例如： 

# 错误示意：
# 使用未来一天的价格决定今天是否买入

future_return = close.shift(-1) / close - 1

signal = future_return > 0

这段代码可以用于研究标签， 但绝对不能直接作为历史交易时点的可用信号。

17.2 常见未来函数来源

来源 错误示例 正确思路
信号与成交混淆 用收盘后才知道的收盘价，在同一收盘价成交 使用下一交易日可实现的价格或明确的撮合规则
财务数据泄漏 在报告发布前使用年度报告数据 按公告日或可用日构建数据
全样本标准化 用整个历史区间均值标准化早期数据 只使用当时可获得的历史窗口
未来滚动统计 使用 centered rolling 等包含未来数据的计算 使用只向后看的滚动窗口
退市股票遗漏 只使用今天仍然存在的股票回测过去 尽量使用包含历史股票状态的股票池
后见之明筛选 只选择后来表现优秀的股票作为历史股票池 在每个时点根据当时规则生成股票池

17.3 幸存者偏差

幸存者偏差（Survivorship Bias）是指研究数据只包含今天仍然存在的资产， 而忽略了已经退市、破产或消失的资产。

例如，如果今天只选择仍然上市的股票， 再回测十年前的策略， 结果可能会比当时真实可投资的股票池更乐观。

17.4 过拟合

过拟合（Overfitting）是量化研究中最常见的风险之一。

例如，一个研究者不断尝试： 

MA = 17
RSI = 63
MACD = 某个参数
持有天数 = 13
止损 = 7.4%

最后在历史数据上找到一组表现极好的参数。 但这组参数可能只是适应了历史噪声， 并不代表未来仍然有效。

常见的应对方法包括：

  • 减少不必要的参数。
  • 使用训练集、验证集和测试集。
  • 进行样本外测试。
  • 进行滚动回测和 Walk-forward 分析。
  • 检查参数敏感性。
  • 避免为了追求历史收益反复修改规则。

17.5 Walk-forward 分析

Walk-forward 的基本思想是： 使用过去一段时间研究或训练模型， 再在之后一段没有参与研究的数据上测试。

训练区间 → 测试区间
向前滚动 → 重新训练 → 再测试

这样可以更接近真实的策略开发过程， 减少一次性使用全部历史数据优化参数造成的偏差。

18. 第十五步：从回测到模拟盘

回测表现良好，并不意味着策略已经可以直接投入真实资金。

在回测之后，通常还需要进行模拟盘或纸面交易。

18.1 为什么需要模拟盘？

因为有些问题无法通过普通历史回测完全发现：

  • 实时数据延迟。
  • 数据字段变化。
  • 交易接口异常。
  • 订单拒绝。
  • 部分成交。
  • 撤单失败。
  • 交易时间判断错误。
  • 实际滑点与历史假设不一致。
  • 程序重启后持仓状态不同步。

18.2 模拟盘应该验证什么？

数据是否按预期更新？
策略是否在正确时间生成信号？
订单数量和价格是否正确？
订单状态是否能够正确跟踪？
账户持仓与系统记录是否一致？
交易成本是否与预期接近？
程序异常后能否恢复？
日志和告警是否完整？

18.3 回测、模拟盘和实盘的关系

回测 验证研究假设和历史表现。
↓
模拟盘 验证实时数据、信号和交易流程。
↓
小资金实盘 验证真实成本、执行和系统稳定性。
↓
逐步扩大规模 只有在策略和系统经过持续验证后，才考虑扩大资金。

19. 第十六步：如何搭建实盘交易系统？

实盘系统和回测系统的最大区别在于： 回测可以重新运行，实盘则需要面对真实资金、真实订单和真实故障。

19.1 实盘系统的核心模块

模块 主要职责
Market Data 接收实时行情和交易状态
Strategy Engine 根据数据生成信号
Portfolio Engine 计算目标持仓和资金分配
Risk Engine 检查单笔、单股、组合和账户风险
Order Manager 创建、提交、撤销和跟踪订单
Broker Gateway 对接券商或交易 API
Position Manager 维护持仓、现金和成交状态
Reconciliation 对比系统记录与券商实际账户
Monitoring 日志、指标、告警和故障监控

19.2 为什么需要订单管理器？

不能简单地在策略中写： 

if signal:
    broker.buy(symbol, quantity)

因为真实交易中，订单存在多个状态：

CREATED → SUBMITTED → ACCEPTED → PARTIALLY_FILLED → FILLED

或： REJECTED / CANCELLED / FAILED

订单管理器需要记录：

  • 客户端订单 ID
  • 券商订单 ID
  • 股票代码
  • 买卖方向
  • 委托数量
  • 成交数量
  • 委托价格
  • 成交均价
  • 订单状态
  • 创建时间和更新时间

19.3 风控必须在订单发送之前

一个合理的实盘链路应该是：

策略信号 → 目标持仓 → 风控检查 → 生成订单 → 订单检查 → 券商接口 → 成交回报

风控可以检查：

  • 是否超过单只股票最大仓位？
  • 是否超过账户最大使用资金？
  • 是否处于禁止交易时间？
  • 股票是否停牌或不可交易？
  • 是否超过每日最大交易金额？
  • 是否出现异常订单数量？
  • 是否存在重复下单？
  • 是否与当前实际持仓冲突？

重要： 自动交易系统必须具备停止交易、撤单和人工接管机制。 任何策略都不应该拥有不受限制的下单权限。

20. 第十七步：推荐的 Python 项目结构

如果以你现在的 STOCK LAB 为基础继续扩展， 我建议把量化研究作为独立的业务模块， 不要把因子、回测和实盘逻辑全部塞进现有行情接口中。

20.1 为什么这样分层？

核心原因是： 不同模块的变化速度不同。

模块 变化特点
数据网关 数据供应商可能变化，需要统一接口
因子 研究者会持续增加和修改
策略 研究假设变化频繁
回测引擎 应保持稳定，避免每个策略重复实现资金逻辑
实盘执行 需要高稳定性和严格测试
前端 展示研究结果、回测报告和交易状态

20.2 因子接口可以怎么设计？

因子最好具有统一的输入和输出形式。

例如： 

from abc import ABC, abstractmethod

import pandas as pd


class Factor(ABC):

    name: str

    @abstractmethod
    def calculate(
        self,
        data: pd.DataFrame,
    ) -> pd.Series:
        """Calculate factor values."""
        raise NotImplementedError

然后具体因子实现： 

class Momentum20Factor(Factor):

    name = "momentum_20"

    def calculate(
        self,
        data: pd.DataFrame,
    ) -> pd.Series:

        close = data["close"]

        return close / close.shift(20) - 1

这样策略只需要知道： 

momentum = momentum_factor.calculate(data)

而不需要知道因子的具体计算细节。

20.3 策略接口可以怎么设计？ 

from abc import ABC, abstractmethod

import pandas as pd


class Strategy(ABC):

    name: str

    @abstractmethod
    def generate_signals(
        self,
        data: pd.DataFrame,
    ) -> pd.DataFrame:
        """Generate strategy signals."""
        raise NotImplementedError

这里的重点不是具体代码，而是接口职责：

  • 因子负责计算特征。
  • 策略负责生成信号。
  • 组合负责计算目标权重。
  • 回测引擎负责模拟交易。

21. 第十八步：一个最小量化系统的开发路线

不建议一开始就开发一个包含机器学习、自动交易、组合优化和复杂回测的庞大系统。 更合理的方法是先做出一个能够验证完整闭环的 MVP。

阶段一：数据与指标

01
获取历史日线

先支持一批股票的 OHLCV 数据。

02
统一数据格式

统一 symbol、trade_date、open、high、low、close、volume、amount。

03
计算基础指标

实现 MA、收益率、波动率、成交量比率等。

阶段二：单策略回测

04
实现一个简单策略

例如 MA20 / MA60 趋势策略。

05
实现单股票回测

模拟持仓、收益、净值和交易记录。

06
加入交易成本

让回测结果从毛收益转向更接近净收益。

阶段三：多股票量化选股

07
建立股票池

支持指定市场、行业、上市时间和交易状态筛选。

08
实现横截面因子排序

例如按动量、PE、ROE 对股票排序。

09
实现组合构建

支持等权、最大持仓数和单只股票权重限制。

阶段四：研究质量

10
加入样本外测试

将研究区间与测试区间分开。

11
加入 Walk-forward

检查策略在滚动时间窗口中的稳定性。

12
加入因子分析报告

展示 IC、分组收益、换手率、回撤和行业暴露。

阶段五：模拟盘与实盘

13
统一信号和目标持仓接口

让回测和模拟盘尽量使用相同策略逻辑。

14
增加订单管理和风控

处理订单状态、资金限制、重复下单和异常情况。

15
模拟盘验证

在不承担真实资金风险的情况下检查整个交易链路。

16
小规模实盘

仅在策略、系统和风险控制经过充分验证后考虑。

22. 第十九步：机器学习与 AI 如何接入？

机器学习可以成为量化系统的一部分， 但它不是量化系统的起点，也不是策略有效的保证。

22.1 传统量化与机器学习量化的区别

方式 规则来源 典型示例
规则型量化 研究者明确编写规则 MA 金叉、低 PE、高 ROE
统计型量化 根据统计关系构建模型 回归、协整、因子模型
机器学习量化 从历史特征中学习预测关系 预测未来收益、分类涨跌、排序股票
深度学习量化 使用神经网络学习复杂非线性关系 时序模型、Transformer、多模态模型

22.2 机器学习量化的基本流程

历史数据 → 特征工程 → 标签构建 → 训练集 → 模型训练 → 验证集 → 样本外预测 → 组合构建 → 回测

22.3 特征与标签

例如，使用过去 20 日动量、波动率、成交量和估值作为特征， 预测未来 20 日收益。 

features = [
    "momentum_20",
    "volatility_20",
    "volume_ratio_20",
    "pe_ttm",
    "roe",
]

target = "future_return_20"

这里最重要的原则是： 特征只能使用预测时点已经知道的信息，标签可以来自未来，但不能泄漏回特征。

22.4 为什么 AI 不应该直接决定买卖？

在实际量化系统中， AI 更适合先作为研究和辅助分析模块，例如：

  • 财报文本结构化。
  • 新闻事件分类。
  • 管理层表述变化分析。
  • 研究假设生成。
  • 因子解释与研究报告生成。
  • 异常数据检测。
  • 策略代码辅助开发。

如果让 AI 直接生成真实订单， 则必须经过严格的信号约束、风控和人工授权机制。

AI 可以帮助理解数据和生成研究假设， 但交易决策仍然需要可验证的规则、风险限制和执行控制。

23. 量化系统中最重要的工程原则

原则一：先保证数据正确，再追求策略复杂

数据错误会污染整个研究链路。 先解决数据时间、复权、重复、缺失和可用性问题， 通常比增加一个新指标更重要。

原则二：研究逻辑与交易执行分离

策略只负责产生信号或目标持仓， 不应该直接管理所有券商接口细节。

原则三：回测和实盘尽量共享核心逻辑

如果回测使用一套策略代码，实盘又重新手写一套， 两者很容易出现行为不一致。

原则四：每个结果都应该可以追溯

一份回测报告应该能够回答：

  • 使用了什么数据？
  • 数据截至什么日期？
  • 使用了哪些参数？
  • 使用了什么股票池？
  • 使用了什么交易成本？
  • 使用了什么成交规则？
  • 使用了哪个版本的策略代码？

原则五：不要把历史收益当作未来承诺

回测只能说明： 在给定数据、规则和假设下，历史上发生了什么。

它不能保证未来收益， 也不能消除市场结构变化、交易成本变化和模型失效风险。

24. 量化分析总结

一个完整的量化系统，本质上是一个将投资研究流程工程化的系统。

  • 数据层： 获取、清洗、标准化和存储历史与实时数据。
  • 因子层： 将价格、财务和其他信息转换成可研究的特征。
  • 策略层： 根据因子或规则生成选股、买卖和目标持仓信号。
  • 组合层： 决定股票权重、仓位、资金分配和风险暴露。
  • 回测层： 模拟历史交易、成交、费用、账户和净值变化。
  • 评估层： 分析收益、回撤、波动率、换手率和策略稳定性。
  • 执行层： 将目标持仓转化为订单，并处理真实成交与异常。
  • 风控层： 限制仓位、资金、订单和系统风险。

如果把整个过程压缩成一句话：

数据 → 因子 → 策略 → 组合 → 回测 → 风险评估 → 模拟盘 → 实盘

真正值得长期建设的量化平台， 不是“拥有多少个指标”， 而是能否让研究过程具备：

  • 可重复
  • 可验证
  • 可回测
  • 可解释
  • 可维护
  • 可扩展
  • 可安全执行

对 STOCK LAB 而言， 未来可以逐步从“股票数据与研究展示平台”， 演进为一个包含 数据研究、因子实验、策略回测、组合分析和交易管理 的完整投资研究工作台。
